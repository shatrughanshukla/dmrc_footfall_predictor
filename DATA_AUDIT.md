# Dataset audit and readiness

Audit date: 2026-10-14. This report describes files present in this repository; it does not certify them as DMRC publications.

## Findings

| Asset | Contents and validation | What it can support | Limitations |
| --- | --- | --- | --- |
| `data/raw/DELHI_METRO_DATA.csv` (243 unique station rows) | Station, line, latitude, longitude. No timestamps or passenger counts. Includes 15 operating stations added from DMRC's March 2026 network map and current network page. | Station directory and approximate topology input. | Coordinates for the 15 added stations are blank pending verification; travel-time edges involving them use the graph's default segment estimate. Original coordinate accuracy is not independently verified. It cannot train footfall forecasts. |
| `data/raw/metro_lines.csv` (9 data rows) | Line, coach count, compartment capacity, total capacity. | Starting point for configurable capacity scenarios. | No source citation, date, occupancy definition, fleets, turnaround, signaling limits, or schedules. Not verified operational data. |
| `data/synthetic/dmrc_calibrated_footfall.csv` (3,361,176 records) | 243 stations × 728 dates × 19 hours (2025-01-06 through 2027-01-03), generated by `pipeline/02_generate_calibrated_dataset.py`. | UI demonstrations and simulation experiments. | Every passenger count is synthetic. Calibration constants, station weights, hourly curves, seasonal factors, and event multipliers are code-authored assumptions, not observed AFC counts. It is not valid evidence of real-world forecast accuracy. |
| `data/synthetic/line_distribution_model.json` | Weighted synthetic line shares for interchange stations. | Scenario allocation only. | No observed OD, AFC, transfer, or line boarding data. It cannot establish real line-wise demand. |
| `data/cleaned/stations_cleaned.csv` | Derived 243-station directory with line membership and interchange metadata. | Network demo, route estimates, and station selection. | “Cleaned” does not mean independently verified; new station coordinates remain blank and their adjacent travel times use the default estimate. |
| `data/cleaned/metro_line_operations.csv` | Hand-authored operational parameters in `pipeline/01_audit_and_clean_data.py`. | What-if scheduling under explicit assumptions. | Fleet sizes, turnaround, headways, signaling minima, load factors and capacities have no row-level traceable references. | `models/*` and `models/evaluation_metrics.json` | Model trained on 23 features; metrics cover 2,922,561 training and 438,615 time-held-out test records, with training through 2026-09-30 and test dates from 2026-10-01 to 2027-01-03. The historical aggregate features are derived from synthetic data; evaluation scores must not be generalized to real DMRC counts. |

## Data gaps

- **Station/time footfall:** no observed count series, dates, intervals, or AFC-derived station entries/exits are present. Forecasts are simulation outputs only.
- **Peak/off-peak:** the synthetic generator encodes assumed hour shapes; there is no observed data to measure actual peak patterns or seasonal effects.
- **Line-wise/interchange demand:** no OD matrices, transfer counts, or line-level passenger counts are present. Current shares are weighted assumptions.
- **Train load and capacity:** project values exist but are not traceably sourced or operationally validated. Boarding clearance is an additional model assumption.
- **Timetable and feasible dispatch:** no current trip-level timetable, service calendar, rolling-stock assignment, turnaround/depot constraints, or signaling documentation is included.
- **Network map:** a hand-authored line sequence exists. Official OTD static DMRC GTFS is publicly listed with stops, routes, stop times, and trips, but last updated Aug. 10, 2023; it is a useful schedule/topology candidate, not current real-time service or passenger counts. The portal requires an access-purpose submission to download, so it has not been silently imported.
- **Model evaluation:** a synthetic chronological split measures reproduction of the generator's own patterns, not out-of-sample performance on observed passengers. No observed-data benchmark is currently possible.

## External source discovery

- Delhi Open Transit Data, [DMRC Static Data](https://otd.delhi.gov.in/data/staticDMRC/): lists 262 stops, 36 routes, 411,686 stop-time records, and 17,997 trips, last updated Aug. 10, 2023. The portal describes stop times as approximate arrival/departure times and requires submission of usage purpose before download. Suitable candidate for static route and timetable replacement after download, license/terms review, and schema audit. Does not provide passenger counts.
- DMRC, [Annual Report 2023–24](https://backend.delhimetrorail.com/documents/7611/Annual-Report-2023-24-English.pdf): reports network-wide journeys and network scope, but this is not a station-by-hour demand dataset. It cannot validate this model's station/hour predictions.
- DMRC, [Operational network map (March 2026)](https://delhimetrorail.com/static/media/DMRC-Network-Map-Hindi-English-VA-23032026.00317293.pdf) and [present network](https://delhimetrorail.com/pages/about-us/present-network): sources for the opened Pink Line and Magenta Line extension sections and current station names included in the directory. These sources do not provide station-by-hour passenger counts or verified coordinates for the additions.

No external records were downloaded or merged into project data in this pass. This avoids treating a portal listing or a network-wide ridership statistic as station-level ground truth.

## Use and release conditions

Use the dashboard only for simulation and software demonstration until verified observed footfall and operational inputs are supplied. Keep raw downloaded data immutable; store cleaned feeds under `data/cleaned/` and generated scenarios under `data/synthetic/`. Record source URL, retrieval date, license/terms, schema checks, and transformations for every import. Retrain and regenerate the evaluation report as one pipeline run; do not publish current accuracy metrics as real-world model performance.

## Audit status

Implemented: explicit synthetic-data/API provenance, date-aware inference for 23 features, a 104-week synthetic scenario set, and a chronological holdout evaluation. The dashboard accepts today and future dates, computes weekdays for any date, and displays listed occasions and the source/status of their calendar entry. Its occasion list is populated through 2028, while fixed annual holidays are included through 2035; an unlisted occasion is not automatically inferred. Not achieved: reliable real-world forecasting or operational timetable optimization. Those require observed passenger counts, traceable train operating data, refreshed network inputs, and validation against held-out observed periods.
